# Research notes for the lean architecture (2026-11-26)

Two Haiku web-research agents. Facts marked UNVERIFIED were not confirmed in primary docs; test them on the box before relying on them.

## R1. Scheduler / service / libraries
- **APScheduler 4.x is pre-release** (latest seen 4.0.0a6, 2025-04-27; its README says it may change incompatibly and is not for production; no migration path from 3.x). Use **3.11.x pinned** (3.11.1-3.11.3 fixed DST, CronTrigger and shutdown bugs; unverified exact latest).
- APScheduler 3.x with a persistent jobstore: a missed run is compared with `misfire_grace_time`; outside the grace it is SKIPPED (silent); `coalesce=True` collapses queued runs into one. Reported default grace is 1 s (UNVERIFIED; read `apscheduler/schedulers/base.py` in the installed version). So: set `misfire_grace_time` per job in hours, `coalesce=True`, `max_instances=1`, explicit timezone; test a DST transition. No Windows-specific issues found.
- **Windows Task Scheduler** as a driver: boot trigger and time triggers exist; StartWhenAvailable / RestartCount / "run whether logged on or not" settings page did not load (UNVERIFIED from memory: needs a stored password, fails silently if the password changes). A tick needs state (last-run records) and a lock to avoid overlaps.
- **Service wrappers:** NSSM stable 2.24 (2014), pre-release 2.24-101 (2017) recommended on Windows 10+; no 2026 activity. WinSW (MIT) maintained, 2.x maintenance-only, 3.x needs .NET 4.6.1; latest release number unconfirmed. Both support restart-on-exit and stdout/stderr redirect with rotation (exact options UNVERIFIED). pywin32 service = more code, not recommended.
- **Other:** cronsim (zero deps, matches Debian cron; version 2.6/2.7 unverified) - already used in this repo. Huey SQLite backend works without Redis but Windows support only anecdotal. rq needs Redis (skip). `schedule` has no persistence/catch-up.
- **tenacity** 9.x: stop_after_attempt/delay, wait_exponential, retry_if_exception_type, async support. Already a locked library in this repo.
- **Locks:** a hand-written PID file fails on stale PIDs after a reboot; prefer an OS lock (`filelock` 4.2.x - fixed CVEs in 4.2.1+; or `portalocker` 3.2.0) plus `psutil` 7.2.2 to check the owner process. (This repo already has a PID+create-time lock in core/process.py that was reviewed as mostly sound; consider keeping it with the race fix rather than swapping.)
- Haiku recommendation: one long-running Python service + APScheduler 3.11.x + NSSM/WinSW, plus an INDEPENDENT Task Scheduler task (boot + 5-min check) that restarts the service if it is down. Failure modes: silent skip past grace; single process crash stops all jobs until restart; NSSM 2.24 bugs on newer Windows; Task Scheduler "run whether logged on" fails silently on password change; service account password expiry.

## R2. rclone 1.74 facts (rclone.org docs, forum)
- `sync` deletes on the destination; `copy` never deletes (safe default). `--backup-dir DIR` moves overwritten/deleted files into DIR (whether DIR must be on the same remote: UNVERIFIED). `--max-delete N` (default -1) is a FATAL error when exceeded; `--max-delete-size` caps deleted bytes. Hard backstop; pass the same threshold as the dry-run refusal threshold.
- Comparison: size+modtime, or hash where available; `--checksum` forces hash+size. GCS stores MD5; modify window default 1ns, gsutil-uploaded files need `--modify-window 1s`. SMB/NTFS 2 s window: UNVERIFIED, test.
- `--retries` (whole-sync, default 3), `--low-level-retries`. **`--ignore-errors` overrides the "no deletes after errors" safety: never use on the sync leg.** `--immutable` fails instead of modifying. `--transfers` 4, `--checkers` 8, `--fast-list` supported by GCS. `--max-transfer` (exit 8) and `--max-duration` (exit 10) are budgets; a stopped run is not a clean success.
- `--use-json-log` + `--log-file`: one JSON object per line (level/msg/source/time). Dry-run JSON field names for counting deletes: UNVERIFIED.
- **No VSS support in rclone** (no `--vss`). Locked files are not solved by rclone; by default rclone aborts a file that changes during upload. Either snapshot yourself or treat locked files as a failed/partial run. (Do not use `--local-no-check-updated` on VSS volumes.)
- `$RECYCLE.BIN` / `System Volume Information` excludes: use `--exclude "$RECYCLE.BIN/**"` and `--exclude "System Volume Information/**"`; behaviour UNVERIFIED, test.
- **Exit codes:** 0 success; 1 generic; 2 usage; 3 dir not found; 4 file not found; 5 temporary (retry may fix); 6 NoRetry; 7 fatal (retry will not fix); 8 --max-transfer reached; 9 success but nothing transferred (only with --error-on-no-transfer); 10 --max-duration exceeded. `--max-delete` has no exit code of its own (fatal). Retryable: 5 (1 maybe once). Never auto-retry 2,3,4,7,8,10.
- **Verification:** `rclone check` compares size+hash; `--one-way` checks source->dest only; `--combined FILE` writes `=` same, `*` differ, `-` dest only, `+` source only, `!` error; `--download` reads both sides fully (expensive). SMB has no hash on the destination, so hash checks read the data: verify weekly, not nightly.
- **RC API** (`rclone rcd` / `--rc`, localhost:5572, auth required; access = shell access): job/status, job/stop, core/stats. Forum reports `job/stop` unreliable and no ETA. Recommendation: subprocess + `--use-json-log` + `--log-file`, no open port; RC only if live stop is truly needed.
- **Writes:** default writes `<name>.partial` then renames (keep it); `--inplace` leaves partial files on failure. Windows long paths use `\\?\` automatically (leave `--local-nounc` off); path elements max 255 chars. Invalid Windows characters are replaced. SMB mounts: forum reports mkdir/chtimes errors; prefer UNC path via the local backend; test long-path/Unicode names before go-live.
- **Dry-run then real run:** dry-run with JSON log, count deletes, refuse above a config threshold, then run with the same `--max-delete`; `--backup-dir` makes deletes reversible. Recommended: `copy` + `--backup-dir` normally; `sync --max-delete N` only where mirror semantics are needed.
- `bisync` is not suitable (two-way).
- Proposed flag sets (verify on the box): GCS leg `copy ... --backup-dir ... --transfers 8 --checkers 16 --fast-list --modify-window 1s --retries 3 --low-level-retries 10 --use-json-log --log-file ... --exclude ...` (no `--ignore-errors`); NAS leg `copy ... --backup-dir ... --transfers 4 --checkers 8 --retries 3 --low-level-retries 10 --use-json-log --log-file ...` with `--checksum` only on the weekly verify.
