### 1. test_w26b_names.py::test_l2_unicode_case_normalization_churn

```
E   AssertionError: ('cloud', ['café.txt', 'മലയാളം രേഖ.xlsx', '😀.pdf'], ['café.txt', 'café.txt', 'മലയാളം രേഖ.xlsx', '😀.pdf'])

E     At index 1 diff: 'മലയാളം രേഖ.xlsx' != 'café.txt'

```

The setup check passed: the source held both spellings of the accented name (NFC and NFD, printed identically here). The NAS check passed for the same listing. Only the cloud (local NTFS stand-in) holds one `café` entry after the sync.

Classification: **UNSURE**, leaning towards rclone's default Unicode normalisation (NFD and NFC names merged into one destination entry) on the cloud leg. The evidence is that NAS keeps both forms and cloud keeps one. If that is what happened, one source file is missing from the cloud copy, which is a product question for the owner, not just a rig question. The test's stated expectation (ONE entry, no duplicate, no loss) does not hold for the cloud leg. Needs a decision: is rclone's normalisation the accepted behaviour, or should both files survive?

### 2. test_w26e_acl.py::test_w26e_L7_acl_denied_subfolder_without_backup_mode

Failing line (test_w26e_acl.py:94, after the test's own cleanup):

```
[L7] ACL restore: ['icacls C:\\...\\case_capbcc68\\source\\FY26-27\\Audit /remove:d rc=5']
PermissionError: [Errno 13] Permission denied: 'C:\\...\\case_capbcc68\\source\\FY26-27\\Audit\\audit_0.txt'
```

The test died before it reached the cloud status assertion (line 104). The run itself behaved as the test expects:
- LAN dry-run failed with robocopy exit 11, "Access is denied" on the `Audit` folder.
- Cloud guard `rclone size` exited 6 ("failed to open directory Audit").
- The flow ended with "Backup completed with 2 error(s)".

Classification: **TEST RIG**. `_restore_access` takes its `probe` from `folder.glob("audit_*.txt")` on the denied folder. The glob returns nothing, so `readable()` returns True straight after the first icacls call (rc=5). The fallbacks (`icacls /reset /T`, `takeown`, the full-control grant) never run. The test then reads a file that is still denied. The docstring says the deny covers READ_CONTROL, so the first `/remove:d` cannot succeed. The fix belongs in the rig: pick the probe path before applying the deny, and make `readable()` fail when no probe exists.

Leftover state: the `Audit` folder under `C:\Users\malliath\AppData\Local\Temp\opencode\aam_lab\case_capbcc68\source\FY26-27\` is still ACL-denied after the run. It is a lab temp folder, not backup data. I did not touch it because the rules say not to fix anything.

**Exact cloud status string for L7: not captured.** The flow log says "Backup completed with 2 error(s)" and the cloud guard failed, but the cloud `run_history` status was not printed. The manifest DB is no longer in the case folder (only `runtime\logs\backup_2026-11-23.log` remains). The test assertion (`CLOUD_NOT_OK = ("CLOUD_FAILED", "CLOUD_BLOCKED")`) was never evaluated.
